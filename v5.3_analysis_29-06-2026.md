## 1. Security Fixes (Masking Layer)

### What Was Broken

The entire gaps/evidence/patterns surface was leaking masked content:

- `reasoning.py:summarize_claim()` — read `claim_node.get("label", "")` with zero `is_masked` check
- `reasoning.py:summarize_all_claims()` — called `summarize_claim()` unconditionally for every CLAIM node
- `reasoning.py:find_gaps()` — called `summarize_all_claims()` unconditionally
- `graph.py:semantic_query()` — iterated `self._embeddings.items()` with no `is_masked` check
- `vector_store.py` — masked node embeddings remained queryable in ChromaDB (embedding covert channel)

### What Was Fixed

| File | Fix | Lines Changed |
|------|-----|---------------|
| `victor/reasoning.py` | `_masked_summary()` static method + masking gate in `summarize_claim()` | ~25 |
| `victor/graph.py` | `is_masked` check in `semantic_query()` cosine loop | 2 |
| `victor/vector_store.py` | `delete_node_chunks()` method + docstring update + `delete_source()` consolidation | ~30 |
| `victor/core.py` | `delete_node_chunks()` wiring in `mask()` method | 6 |

### Propagation

The `reasoning.py` fix propagates automatically:
- `summarize_claim()` → called by `summarize_all_claims()` → called by `find_gaps()`
- `summarize_claim()` → called by `PatternDetector.analyze()` → called by `_inject_pattern_note()`

All three entry points (CLI gaps, CLI evidence, ask_full pattern injection) are now protected.

### Remaining Architectural Issue

`delete_node_chunks()` is a no-op for claim nodes because ChromaDB chunks use paper `source_id`, not claim `node_id`. This is architectural (claims don't have their own ChromaDB chunks) — the embedding covert channel remains open at the paper chunk level. Not a priority until MCP server ships (single-user local deployment has no attacker).

## 3. MarkdownIngestor `--type` Flag

### Problem

`MarkdownIngestor` hardcoded `NodeType.NOTE` (epistemic weight 0.50) for all `.md`/`.txt` files. Real research papers should use `NodeType.PAPER` (epistemic weight 0.70, LITERATURE tier).

### Solution

Three-file change:
1. `ingest.py`: `MarkdownIngestor.ingest()` accepts `source_type` parameter
2. `core.py`: `ingest_file()` threads `source_type` through via `inspect.signature` check
3. `cli.py`: `victor ingest` has `--type paper|note` option

### Epistemic Weight Chain

```
source_type="paper" → NodeType.PAPER → _DEFAULT_EPISTEMIC[NodeType.PAPER] = EpistemicStatus.LITERATURE → weight 0.70
source_type=None    → NodeType.NOTE  → _DEFAULT_EPISTEMIC[NodeType.NOTE]  = EpistemicStatus.NOTE      → weight 0.50
```

## 5. SciFact Benchmark with ModernCE

### Configuration

- Model: `dleemiller/ModernCE-large-nli`
- Label order: `entailment,neutral,contradiction` (correct for ModernCE)
- Mode: cross-check (LLM decides, NLI catches agreement bias)
- n=100 samples

### Result

**35.0% accuracy — FAIL** (vs. 71% baseline with deberta-v3, vs. 85% PRD target)

| Direction | Precision | Recall | F1 |
|-----------|-----------|--------|----|
| confirm   | 66.7%     | 20.0%  | 30.8% |
| contradict| 28.4%     | 70.0%  | 40.4% |

**NLI overrides fired: 49/100** — ModernCE is flipping correct LLM judgments to wrong ones.

### Confusion Matrix

```
Gold \ Pred     confirm  contradict  inconclusive
confirm (70):      14        53            3
contradict (30):    7        21            2
```

### Diagnosis

ModernCE is trained on MNLI (news/Wikipedia/fiction), not scientific text. The domain gap is too large. The cross-encoder's confidence scores are unreliable for scientific claim verification, causing it to override correct LLM predictions with wrong ones.

**Key insight:** The cross-check architecture — "LLM decides, NLI occasionally objects" — only works when NLI is accurate enough to be trusted. At 35%, ModernCE is worse than random. The path forward is a scientifically fine-tuned model, not a better general-domain model.
